# coarsecl — progress write-up (2026-07-08)

*A plain-language account of what we built, what we found, why the results look the
way they do, and where to go next — framed against the overall goal and the
Complementary Learning Systems (CLS) angle we're trying to move toward.*

---

## 1. The goal, and the CLS framing

**The plain question.** When a network learns 100 fine-grained classes one small
batch of classes at a time (class-incremental, no task ID at test, no replay
buffer), it catastrophically forgets the earlier ones. We are testing one specific
intervention: **does giving the network coarse-grained category knowledge (which of
the 20 CIFAR-100 superclasses a thing belongs to) reduce that forgetting?** Nothing
else is under test — no replay, no fancy CL machinery — so any effect we see is
attributable to the coarse signal alone.

**Why this is a CLS question.** Complementary Learning Systems theory (McClelland,
McNaughton & O'Reilly 1995; Kumaran, Hassabis & McClelland 2016) says the brain
avoids catastrophic forgetting by splitting learning across two systems:

- **Neocortex** — *slow*, learns structured overlapping representations, extracts
  regularities and **schemas** (category-level gist), generalizes. Must learn slowly
  and interleaved or it too suffers interference.
- **Hippocampus** — *fast*, sparse **pattern-separated** representations, stores
  specific episodes without overwriting old ones, and **replays** them to teach the
  cortex gradually.

A key prediction of CLS: **schema-consistent information is easier to consolidate**
(Tse et al. 2007) — an existing cortical schema scaffolds and protects new learning.

Our two components map cleanly onto this:

| Our component | CLS analogue | Role |
|---|---|---|
| **Coarse system** (20 superclasses, trained upfront, frozen) | Neocortex / **schema** | Stable, structured "gist" of the world |
| **Fine system** (100 subclasses, learned sequentially) | The fast specific learner | Acquires new detail, but forgets |

So the project is really asking a stripped-down CLS question: **if the cortical
schema is present and informs the fast learner, does that alone protect it from
forgetting?** We have deliberately removed the *other* CLS ingredients (pattern
separation, replay) so we can see the schema's raw, isolated contribution.

---

## 2. What we built

A config-driven experimental scaffold where two things are swappable **by config, not
code edits**:

- **`coarse.source`** — where the coarse signal comes from: `none` (baseline),
  `oracle` (ground-truth one-hot), `soft` (a synthetic distribution whose peakedness
  is set by one `smooth` knob), `trained` (softmax of a separate coarse CNN).
- **`conditioning.mechanism`** — *how* the coarse signal enters the fine classifier:
  - **`concat`** — the coarse distribution is fed in as an **input feature**.
  - **`gate`** — the coarse distribution acts as an **inference-time structural
    constraint**: it hard-masks / adds a log-prior to the fine logits, keeping only
    the ~5 fine classes belonging to the indicated superclass.
  - (`aux_loss` also exists; it did not help and is not central here.)

Everything is one YAML per run inheriting `base.yaml`; metrics and resolved config
are written to `results/<run>/`. This is what lets a "fifth condition" be a config
change rather than a training-loop rewrite.

---

## 3. What we found (the headline)

Main run: 60 epochs, all conditions, job `11117190`. **`retained`** = mean accuracy
on *old* tasks across the run (the thing forgetting destroys). **`avg_acc`** = mean
accuracy over all classes seen so far.

| Condition (60 ep) | mechanism | avg_acc | retained | old-task evals > 0 |
|---|---|---|---|---|
| a_baseline | none | 0.088 | 0.000 | 0 / 45 |
| b_oracle | **concat** | 0.096 | **0.000** | 0 / 45 |
| c_soft | concat | 0.096 | 0.000 | 0 / 45 |
| d_trained | concat | 0.086 | 0.000 | 0 / 45 |
| **e_gate_oracle** | **gate** | **0.198** | **0.180** | **45 / 45** |
| e_gate_soft (smooth=0.3) | gate | 0.094 | 0.000 | 0 / 45 |
| e_gate_trained | gate | 0.090 | 0.007 | 35 / 45 |

**The one-sentence result:** *the exact same perfect coarse signal produces **zero**
retention when supplied as an input (concat) but roughly **doubles** overall accuracy
and gives real, sustained old-task retention (0.18) when supplied as a structural
constraint (gate).*

The retention is genuine, not a within-5 chance floor: old tasks hold meaningful
accuracy that decays gracefully with recency (task 0 holds 0.48 → 0.61 → 0.67 in the
early phase before slowly declining), and every one of the 45 old-task evaluations is
above zero.

## 4. Why we're getting these results

Four separate mechanisms explain the whole picture. This is the part that matters for
the thesis.

### 4.1 Input vs. structure: *where does the "skill to use the hint" live?*

Concat gives the network the coarse label as extra input. But the network still has
to **learn to use** that input — and that skill is stored in the same plastic weights
that store the fine knowledge. When those weights are overwritten by the next task,
the skill-to-use-the-hint is overwritten *along with* the knowledge. So concat buys
nothing for forgetting.

> **CLS reading:** the cortex handing the hippocampus a note doesn't help if the
> hippocampus forgets how to read the note. A schema only protects if it acts from
> *outside* the plastic substrate.

The gate does exactly that. It restricts the output space (only the true
superclass's ~5 fine classes are eligible) using logic that lives *outside* the
trained weights. That constraint **cannot be forgotten**, because there's nothing to
overwrite. This is schema-as-scaffold rather than schema-as-input — and it's the
crux of the whole result.

**We confirmed this directly** with a withhold ablation (`b_oracle_withhold`): train
concat *with* the oracle but feed it a *uniform* coarse vector at test time. It
collapses to 0.017 — *below baseline*. So concat's numbers were entirely a test-time
crutch; there was no internalized protection at all.

### 4.2 The gate needs a *peaked* prior — fidelity = confidence, not correctness

`e_gate_soft` (smooth=0.3) gives **zero** retention, and `e_gate_trained` only
partial. Why, when the gate works so well with the oracle?

Because forgetting shows up as a **huge logit gap**: the current task's classes get
logits tens of units above old classes. The gate helps by adding a prior that lifts
the correct superclass. But a *soft* prior only contributes a few logits of
separation (~3.9 for smooth=0.3) — nowhere near enough to overcome a
tens-of-units recency gap. The trained coarse net helps only when it happens to be
confident (peaked), which is why it lands in between (35/45 old evals survive).

> **The operative variable under gating is the schema's *confidence/peakedness*, not
> whether its argmax is correct.** This is a clean, slightly counterintuitive finding
> and suggests a nice figure (see §7, the smooth-sweep).

### 4.3 The forgetting is **head-level**, not feature-level

We built a frozen-feature experiment to test the intuitive hypothesis "if the
features stopped drifting, old classes would survive." We took the coarse net's
features (frozen, BN fixed, no gradient) and trained only a linear fine head:

|  | no gate | gate (oracle) |
|---|---|---|
| **plastic features** | avg 0.088, ret 0.000 | avg **0.198**, ret **0.180** |
| **frozen block-2 features** | avg 0.083, ret 0.000 | avg 0.099, ret 0.018 |

**Freezing features gave no retention benefit — it actively hurt.** So catastrophic
forgetting here is *not* feature drift. It's the **linear head**: masked
cross-entropy on the current task actively pushes *down* the logits of old classes.
The head unlearns old classes even if the features underneath are perfectly stable.

This reframes the whole problem: the target for any "past 0.20" work is the
**classifier head's active suppression of old-class logits**, not representation
stability.

### 4.4 The residual wall: coarse info is *structurally blind* to within-superclass detail

The gate narrows the decision from 100-way to 5-way. But the 5 subclasses inside a
superclass are **spread across different sequential tasks**, so they still forget
relative to each other — and coarse information carries **exactly zero** signal to
disambiguate them (they're all the same superclass). Post-mask old-task accuracies
sit at 0.01–0.28: mostly wrong *even within the correct 5*.

So coarse-alone floors at roughly **chance-within-a-superclass (~0.20)**. This isn't
a bug to fix — it's a **fundamental ceiling of schema-only support**:

> **A schema protects *between-category* knowledge; it is structurally incapable of
> protecting *within-category* detail.** That within-category detail is exactly what
> the fast, forgetting-prone system was for — and it's the part CLS protects with
> pattern separation + replay, which we deliberately removed.

### 4.5 Sanity check: is 0.20 just a bad model? No — the gap is all forgetting

A from-scratch fine backbone trained **jointly** (all 100 classes, non-continual)
hits **0.770**. Continual training gets 0.09–0.20. So the architecture and data
support 0.77; **the entire gap to 0.20 is forgetting, not weak features.** There is
huge headroom, and it is all a CL problem. (Frozen coarse features cap lower, ~0.57 —
that's the subject of §4.6.)

### 4.6 The other channel: learning from the coarse system's *internal representations*, not just its label

Everything in §4.1–4.2 treats the coarse signal as a **label-space** object — a
20-dim distribution, whether fed in as input (concat) or as constraint (gate). But
there is a second, arguably more CLS-faithful channel: let the fine learner build
**on top of the coarse system's internal features** — its distributed schema — rather
than on top of its output label. In the brain the two systems share and transform
*representations*, not one-hot category codes. This is the representation-space
version of "the schema informs the fast learner," and it's a distinct axis from the
input-vs-structure question in §4.1.

We probed it two ways.

**(a) How much fine detail survives at each depth of the coarse net** — freeze the
coarse features at various taps, train a fine probe jointly, measure accuracy:

| tap point | joint fine acc |
|---|---|
| block1 (early) | 0.461 |
| **block2 (middle)** | **0.573** |
| block3 (penultimate) | 0.476 |

An **inverted-U**: the *middle* layer preserves the most within-superclass detail.
This makes mechanistic sense — the coarse net is *trained to collapse* subclasses
into superclasses, so its top layers deliberately discard exactly the fine
distinctions the fine task needs. The middle layer is the sweet spot: abstract enough
to be useful, not yet coarse-specialized. (This matches the general intuition that
mid-level representations transfer better than task-specialized top layers.)

**(b) Does building the fine learner on frozen coarse features reduce forgetting?**
The 2×2 (job `11319272`, 60 ep) — take the block-2 coarse features, freeze them (BN
fixed, no gradient), and train only the fine head on top:

|  | no gate | gate (oracle) |
|---|---|---|
| plastic features | avg 0.088, ret 0.000 | avg **0.198**, ret **0.180** |
| **frozen block-2** | avg 0.083, ret 0.000 | avg 0.099, ret 0.018 |

Two lessons, pointing the same way:

- **Representation *stability* is not what's missing.** Freezing the features — making
  the representation perfectly stable — gave *zero* retention benefit without the gate
  and was ~10× *worse* than plastic *with* the gate. This is the evidence behind §4.3:
  forgetting isn't feature drift, so freezing the substrate can't fix it.
- **Given the gate, feature *quality* dominates; stability is irrelevant or harmful.**
  Plastic fine features (0.77 joint ceiling) beat frozen coarse features (0.57
  ceiling) ~10× on gate-retention. The coarse features have *already thrown away* the
  within-superclass information the fine task needs, so building on them starts the
  fine learner ~20 points below a from-scratch backbone.

**Conclusion for this channel:** *hard* reuse of the coarse system's internal
representations — freeze them, learn fine classes on top — is a **dead end** for
forgetting. It doesn't touch the head-level forgetting (§4.3), and it caps feature
quality below a plastic backbone. The negative result is itself informative: the
schema's *distributed representation* is no better able to protect within-superclass
detail than its *label* is, because it has discarded that detail by construction —
the same granularity wall from §4.4, now shown to hold in feature space too.

What this does **not** rule out is *soft* representational coupling: keep the fine
features plastic and *regularize* them toward the coarse schema (a distillation /
consolidation pull from the stable system), rather than freezing or replacing them.
That is the genuinely CLS-faithful version — the cortical schema *shaping* the fast
learner's representation instead of substituting for it — and we have not tested it.
It's carried forward as a proposal in §7.

## 5. Where this sits relative to CLS

What we've shown, in CLS language:

1. **A cortical schema, supplied as an input, does not protect the fast learner** —
   because the ability to exploit it is itself stored in the forgetting substrate.
2. **The same schema, supplied as a structural constraint, does protect it** (~2×) —
   because the constraint lives outside the plastic weights. This is a concrete,
   isolated demonstration of *schema-as-scaffold* for continual learning.
3. **Schema protection degrades with schema confidence**, not correctness — a
   graded, testable relationship between schema fidelity and consolidation benefit.
4. **The protection has a hard ceiling** at the schema's granularity: it cannot touch
   within-category forgetting. That residual is precisely the job of the CLS
   ingredients we removed (pattern separation, replay).
5. **Sharing the schema's *representation* (not just its label) does not help either**
   — hard reuse of the coarse net's internal features (§4.6) neither protects old
   classes nor matches a plastic backbone's quality, because the schema's
   representation has already discarded within-category detail. Only *soft* coupling —
   the schema shaping rather than replacing the fast learner's features — remains
   untested, and it's the most CLS-faithful thing still on the table.

That fourth point is the honest bridge to "getting closer to CLS": we've mapped
exactly what the neocortical schema alone can and cannot do, which tells us precisely
what the hippocampal half would need to add.

---

## 6. The decision in front of us

**Path A — consolidate.** Accept "coarse-as-structure halves forgetting but is
bounded by a granularity wall" as the result. Multi-seed the headline conditions,
write it up as a clean existence-proof. This is genuinely publishable and honest, and
it's a real CLS contribution (points 1–4 above).

**Path B — push past the wall.** Attack the head-level forgetting we diagnosed in
§4.3. This is where numbers above 0.20 live, and it's the direction that actually
*builds toward* a full CLS (adding a hippocampal-flavored complement to the cortical
schema). But some options here expand scope beyond "does the coarse signal help."

My recommendation: **do the cheap consolidation work regardless (multi-seed +
smooth-sweep), then take one or two low-cost steps into Path B that stay CLS-faithful
before deciding whether to fully commit.** Details below.

---

## 7. Proposals — concrete next steps, roughly by cost

### Immediately (do these no matter which path)

1. **Multi-seed the headline three** — `a_baseline`, `b_oracle` (concat),
   `e_gate_oracle` — for mean ± std. The gate effect (0.18 retained) is large but
   currently single-seed and the whole regime is seed-noisy. This is required before
   any claim is thesis-grade. *(Open item #12.)*

2. **The `soft.smooth` sweep under the gate (0 → 1).** Cheap, and it directly traces
   §4.2: at what peakedness does gating stop protecting? This produces a **schema-
   fidelity → forgetting-protection curve**, which is a compact, CLS-relevant figure
   (schema confidence vs. consolidation benefit). *(Open item #14.)*

3. **Housekeeping:** report `avg_acc` + `retained` + AIA as the headline metrics;
   `average_forgetting` misranks the conditions here and shouldn't lead. Add a loud
   failure if CUDA isn't available (silent CPU fallback has bitten us). *(Items #8, #9.)*

### Path B options, in increasing CLS-fidelity

4. **Loss masking to the current task only** (cheapest, most direct test of the §4.3
   diagnosis). Don't let the CE gradient push down old-class logits. If forgetting is
   really the head suppressing old classes, this alone should lift retention. Minimal
   CL machinery; a clean controlled test of our own mechanistic claim.

5. **Nearest-Class-Mean (prototype) head under the gate** — replace the trainable
   fine logits with stored class-mean prototypes in feature space; the gate restricts
   scoring to the superclass's prototypes. **NCM heads don't forget** because they
   store means, not gradient-updated weights. This is the single best bang-for-buck:
   it directly removes the head-level forgetting *and* it reads cleanly as CLS — a
   small, stable **episodic prototype store** (hippocampal flavour) sitting on top of
   the slow feature/schema system. Strongly recommended first real Path-B experiment.

6. **Soft representational coupling to the schema** — the forward path out of §4.6.
   *Hard* feature reuse (freezing coarse features) was a dead end, but the untested
   alternative is to keep the fine features **plastic** and add a regularizer that
   pulls them toward the (stable) coarse schema's representation — a feature-space
   distillation / consolidation loss, optionally anchored at the middle layer where
   the inverted-U says fine detail is best preserved. This is the most CLS-faithful
   idea still open: the cortical schema *shaping* the fast learner's representation
   rather than replacing it. It attacks forgetting at the representation level while
   §4/§5 attack it at the output/head level, so it's complementary to (4) and (5).
   Higher-risk than NCM, but it's the one that most directly embodies the CLS claim.

7. **Schema-routed expert heads** — the coarse signal routes to a per-superclass
   sub-head (mixture-of-experts). This does *pattern separation at the parameter
   level*: different superclasses use different parameters, so cross-superclass
   interference is removed structurally. It won't by itself fix within-superclass
   across-task forgetting (that's one expert's internal problem), but combined with
   (4) or (5) it's a coherent CLS architecture: schema as router + local stable store.

8. **Latent/generative replay from the coarse-conditioned system** — the fullest CLS
   move: the slow system regenerates old-class representations to interleave, i.e.
   literal hippocampal replay. **This is the endpoint that would make the system a
   genuine CLS** — but it explicitly re-introduces replay, which the current project
   scoped *out*. Flag it as a deliberate scope expansion / the natural "phase 2"
   thesis chapter, not something to slip in silently.

### Suggested sequence

`multi-seed + smooth-sweep` (locks the current result) → **NCM-head-under-gate** (#5:
biggest, cleanest, CLS-shaped step past the wall) → in parallel or next, **soft
representational coupling** (#6: the representation-level complement, most CLS-faithful
open idea) → if those pay off, **schema-routed experts** (#7) → and only as an explicit
new phase, **replay** (#8) for the full CLS.

Each step is a config/module addition, not a rewrite, and each has a clean CLS
interpretation — so whichever we stop at, the story stays coherent: *we started from
the cortical schema alone, showed exactly what it can and can't protect, and then
added the minimal hippocampal complement needed to cover the gap it structurally
leaves.*
