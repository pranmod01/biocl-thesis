## 1. CLS framing (answer to "how does this fit the dual-system picture")

The 07-08 write-up called the fine net "the fast learner". With replay in, the
mapping is:

| component | CLS role |
|---|---|
| replay buffer | hippocampus: fast episodic store, interleaves old experience |
| fine net | neocortex learning new material: slow, distributed, needs interleaving |
| coarse net | pre-existing schema (Tse et al. 2007) |
| EWC | synaptic consolidation, vs replay's systems consolidation |

- The no-replay floor reproduces McClelland et al. (1995): a distributed learner
  without interleaving gets overwritten.
- The coarse signal did nothing on the floor and helps with replay. That is the CLS
  prediction: schemas speed consolidation, they don't replace it (Tse 2007;
  McClelland 2013). The thesis-level claim is an **interaction** (schema ×
  consolidation), not a main effect.
- Two ways the current system falls short of a real dual system:
  - The coarse net is trained upfront on coarse labels for all 100 classes' images,
    so it has seen future tasks. It's a fixed prior, not a learner in the stream.
  - The buffer is passive and never interacts with the schema.
- Superclass recurrence (task split, order_seed 0): each superclass appears in 3–5 of
  the 10 tasks, and all 20 have appeared by task 4. A continual coarse learner would
  face a far less non-stationary stream, so it would be the stable system by
  construction (`coarse.trained.continual`, still unimplemented).
- Proposed sequence: seed decay → decay with trained teacher (#2) → continual coarse
  learner (#3) → schema-guided replay (#4) → generative replay.

## 2. Code added (uncommitted)

- **`cl.replay.priority`**: `none` | `hardness` | `schema`. This changes which
  exemplars are replayed, never what is stored.
  - `schema` scores routing error, 1 − ⟨schema(x), P_fine(superclass | x)⟩.
    `hardness` scores 1 − P_fine(true class) and is the schema-free control.
  - Scores are computed on clean (test-transform) images in eval mode, every
    `priority_refresh` (50) steps.
  - Draws are `(1 − priority_mix)` uniform + `priority_mix` × score/Σscore.
    `priority_mix` defaults to 0.5.
  - An infinite `_PrioritySampler` reads the live weights, so the DataLoader is never
    rebuilt mid-task.
- **`priority_schema`**: `oracle` | `soft` | `trained`. Independent of `coarse.source`,
  so a plain baseline can have schema-guided replay. `oracle` reads the superclass off
  the stored label, which is training-time information only.
- **`priority_level: superclass`**: scores averaged per superclass,
  R_s = Σ q_j(s) r_j / Σ q_j(s). Replay slot i gets weight Σ q_i(s) R_s.
  - It's per-exemplar weight R_s, not "pick a superclass w.p. R_s". Otherwise a
    superclass with one seen fine class would get as much replay as one with five.
- **`priority_probe_per_class: k`**: the first k stored exemplars per class are held
  out, never replayed, and used only to estimate R_s. They count against
  `buffer_size`, so the replay pool is 1800 at the end.
- `priority: none` takes the original shuffle-loader path unchanged. A separate
  `sample_rng` keeps the stored buffer identical to a uniform run with the same seed.
- Each priority run logs one line per task:
  `[replay:...] task k: score first -> last, ESS, R max/mean`.
- `build_coarse_source(cfg, device, source=None)` builds a named source.
  `build_cl_methods(cfg, device=None)` now takes the device.
- `tests/test_cl_methods.py` gained two sections:
  - **Scores:** independent recompute of both scores, uniform floor, re-score
    cadence, buffer equals the uniform run's.
  - **Superclass/probe:** probes disjoint from replay, stored set equals the uniform
    run's, R_s equals the per-superclass mean, equal slot weights within a
    superclass under the oracle schema.

  It passes.
- `results/_jobs/cl_combo_hippo.sh [first_gpu] [cfg ...]` now takes config names.

### Findings

- **Final avg is a single noisy evaluation.** Uniform-equivalent runs span 0.255–0.379.
  mix0 has the best retained/AIA of the four, but the worst final avg: its newest
  task hit 0.85 at the last boundary and old tasks fell to 0.13–0.26.
  - **Rank single runs on retained + AIA.** Report final avg but don't rank on it.
  - This also rules out the priority *code path* (i.i.d. draws with replacement) as a
    cost.
- **Every prioritization slightly hurts retention.** Five of six priority runs are
  below the uniform retained range, and they average 0.322 vs 0.376. The only one
  inside it (schema_trained) had the flattest priority.
  - **Per exemplar:** buffer scores collapse to ~0.02 by mid-task, because the model
    memorizes its buffer. Priority then piles onto the last unmemorized exemplars
    (ESS down to 0.40).
  - **Probes fix the signal.** Probe routing error stays 0.5–0.75 through each task,
    because probes are forgotten rather than memorized.
  - **But the superclass push is gentle and still doesn't help.** R max/mean is
    1.3–1.7, and ESS ≥ 0.95.
  - **In this setup, replay diversity beats targeting.** Suggest dropping the
    priority line.
- **#2: the learned teacher gives no gain.** Decay-trained is inside the uniform range
  on retained/AIA.
- **Re-read of 09-13 runs on retained.** Decay-oracle's lead shrinks to ~1.4 sd
  (0.429). Gate-trained sits at the top of the range on retained (0.418) and above
  it on AIA (0.541).
  - Every deployable coarse route still hinges on coarse-net quality (Item 11), and
    on seeds.

## 4. Literature benchmark (Split CIFAR-100, 10×10 class-IL, from scratch)

- **X-DER Table I** (ResNet-18, 50 ep), final avg accuracy:
  - Joint 70.4
  - Finetune 9.4 (forgetting 89.8)
  - ER 22.1 / 38.6 at buffer 500 / 2000
  - ER-ACE 38.8 / 49.7
  - iCaRL 46.5 / 49.8
  - DER++ 38.3 / 53.6
  - X-DER 49.9 / 59.1
- **DER paper**, AIA at 2000 exemplars: iCaRL 65.3, BiC 68.8, WA 69.5, DER ~75,
  joint 80.4.
- **Our setup reproduces the standard numbers:** floor 8.8, EWC ≈ finetune, replay-2000
  31–38 vs ER 38.6, joint 77.0.
- Our ER-500 is weak (12 vs 22), probably from buffer overfitting at 60 ep/task.
- **We sit on the weakest standard replay baseline.** A reviewer will ask whether
  coarse gains survive a stronger method.
- **ER-ACE-style baseline is config-only:** replay plus `train.loss_scope: current`.
  Replay's CE always uses the full seen mask.
